# 记录工作室使用指南

适用版本：2026 年 10 月 27 日，GitHub main 提交 f0716a0。

版本提示：本文保留的是旧版操作说明。更新至 `919cbe7` 后，作品库、外部导入和记录编辑入口已由自动同步的“战役记录”取代，视觉小说改为所有成员在自身权限内使用的四步向导。当前操作请看[完整演示故事的制作部分](DEMO_STORY.zh-CN.md#从这场故事制作记录)和[新版视觉小说说明](VISUAL_NOVEL.md)，不要再按本文查找旧导入入口。

记录工作室把已经发生的跑团记录整理成染色文本、视觉小说回放和 PDF。第一次使用，建议先完成“同步记录 → 创建玩家公开快照 → 导出 PDF”，再配置素材和配音。本指南按当前网页端的入口编写；界面为英文时，可对照括号中的英文名称。

## 一 进入工作室

登录后，先在左侧选择服务器和战役频道，再点击“制作”下的“记录工作室”（Log Studio）。顶部依次有作品库、导入、记录编辑器、视觉小说、配音工作室、素材、PDF、已发布。点击“返回聊天”可回到跑团界面。

KP 可以导入和整理原始记录、管理制作设置、审核素材及发布成品。玩家只看到自己有权限的内容，部分管理入口不会显示。第一次完整体验建议使用测试服务器的 keeper 账号；测试账号密码为 password。

测试入口：[本地记录工作室](http://127.0.0.1:5175/)。这个地址只在运行测试服务器的电脑上有效。

## 二 先认识项目 快照和演出

项目是装载记录的工作目录。同一个项目可以同步平台聊天，也可以导入外部日志。记录中的原话会保留；编辑器主要用于整理角色、事件类型和场景。

快照是某次选定记录的固定版本，例如“第一晚 玩家公开版”。PDF 和演出都以快照为基础。聊天新增、项目重新分类或角色映射变化后，旧快照不会自动更新，需要重新同步并创建新快照。

演出是快照上的呈现配置，包括背景、立绘、对白框、配音和转场。同一个快照可以制作多份演出。修改背景或朗读文字不会改写聊天原文，也不会把画面里的细节写回剧情知识。

## 三 最短流程 制作第一份 PDF

1. 进入“作品库”（Library），在“记录项目”输入名称，例如“黑水湾 第一场”，点击“创建”，再选中这个项目。
2. 在“从战役记录同步”选择“整场战役”。如果只要某一场，可以改选指定场景、Session 时间范围或事件序号范围；聊天窗口筛选可以留空。
3. 点击“同步事件”（Pull events），确认项目的事件数量增加。
4. 在“快照”区域输入名称，选择“玩家公开版”（PL public version）和“全部事件”，点击“创建快照”。
5. 点击该快照的“查看”，检查下方染色记录。确认人物、顺序、骰点和可见内容符合预期。
6. 点击顶部“PDF”，选择 classic 模板。第一次可保留默认的 A5 纵向、字体和页边距，不勾选文档附录。
7. 点击“渲染 PDF”。任务完成后，点击“预览”检查中文和分页，再点击“下载”。

不需要 PDF 时，可以直接使用快照行中的 HTML、JSON、TXT 或 SealDice TXT 导出。JSON 是平台的版本化交换格式，不是通用于所有海豹版本的 JSON 格式。页面下方的 OOC、时间、骰点和字号开关用于当前阅读预览，不代表会自动修改已下载文件或 PDF 配置。

## 四 导入海豹或其他外部日志

先在作品库建立或选中项目，再进入“导入”。可以上传 TXT、JSON、LOG 文件，也可以直接粘贴日志文本；两者都有内容时，页面优先使用选中的文件。

1. 先选“自动检测格式”，点击“解析并预览”（Parse & preview）。检测不正确时，再手动选适配器。
2. 查看解析报告里的编码、事件数量、发言者和未识别记录。少量无法识别的行会保留原文并列出问题，不会自动丢弃整份日志。
3. 在“角色映射”中把昵称对应到角色。一个调查员换过昵称时，把不同昵称都映射到同一角色；核对 pc、gm、npc、dice 等身份。
4. 检查预览中的中文、多行文本、骰点和时间顺序。确认无误后点击“确认并保存”（Confirm & save）。

“drop”会排除该发言者的记录，只有确定要排除机器人闲聊等内容时才勾选。需要保留完整来源时，保持不勾选，并另存原始导入文件。

当前支持平台原生 JSON、经适配的 SealDice 文本与 JSON、QQ 导出以及 story-painter 染色文本。不是任意染色 HTML 网页都可以导入；具体格式范围可展开“格式兼容说明”查看。发生乱码或编码错误时，先把文件另存为 UTF-8，再重新预览，不要把乱码当成正确内容保存。

## 五 整理角色与场景

在“记录编辑器”（Log editor）中，可以按类型、发言者、场景或正文搜索筛选事件；每次最多显示前 600 条匹配记录，长日志需要缩小筛选范围。

把台词、行动、旁白、骰点和 OOC 分类正确后，再检查发言者到角色的映射。原文列只读，避免整理过程中改变实际发生的内容。对外部导入的记录尤其要核对公开、角色或 GM 可见范围。

需要分章时，在某条事件旁点击“scene”剪切按钮，输入从这一行开始的新场景标题。场景列表支持改名和合并；合并对话框需要填写目标场景的 scene key，可从列表复制。场景切分建议只供选择，点击应用后才生效。

整理完成后返回作品库创建新快照。已经建立的旧快照和它的 PDF 不会跟着变化。

## 六 选择正确的阅读范围

“守秘人完整版”（gm_full）用于 KP 自己查看，可能含私聊与 GM 信息。“玩家公开版”（pl_public）用于制作玩家共同阅读或对外分享的版本。“我的角色视角”（character）只在当前账号拥有角色时显示；当前网页入口使用账号的第一个角色，并没有任意角色选择器。

玩家组共享聊天视角，不等于某个制作快照自动变成全组公开作品。快照仍有自己的阅读范围，发布给频道玩家或持链接者必须使用玩家公开版。

KP 知识和玩家组知识独立。工作室不会把 KP 文档直接作为玩家知识来源；玩家收到的提醒也不等于可以导出整份 KP 知识。

## 七 制作视觉小说回放

最新版本已经有四种外观模板和“从聊天记录生成视觉小说”入口。它组织已有台词，不负责补写剧情，也不会自动生成缺失的美术素材。

### 让系统先整理一个演出草稿

KP 在“视觉小说”页找到“Generate a visual novel from the chat log”。选择来源、外观模板，按需填写制作要求，然后点击“Generate script”。

来源有三个选项：全部聊天窗口、仅玩家可见台词、作品库当前打开的快照。全部窗口会生成 KP 专用快照；想给玩家观看时应选仅玩家可见台词。使用已有快照可以沿用前面选好的场景范围。

系统会整理场景和人物站位，优先使用已批准的背景、立绘和音乐。任务完成后点击“打开”，检查被隐藏的行、场景顺序、背景选择及素材需求，再决定是否发布。未配置真实 LLM 时使用标记为 Mock 的规则整理器。

如果使用云端模型，需要先由 KP 在作品库的“战役制作设置”允许云端处理，并在生成面板确认发送本次所选台词。一次任务默认最多处理 2,000 行；更长的战役先分场景或按范围制作快照。

### 手动建立和调整演出

也可以先打开一个快照，点击“从快照创建演出”。左侧选择场景与台词，中间预览画面，右侧调整背景、人物位置、转场和表演指令，底部时间线用于跳转。

预览下方的“Look template”可以选择 Classic ADV 底部对话框、Novel page 全页文字、Case file 调查档案或 Cinematic 电影字幕。还可以调整文字比例、配色、名字显示、画面色调等；修改后会自动保存。

单句可拆成多个展示片段，也可勾选多句后合并展示或隐藏。这里改变的是呈现方式。朗读需要改读法时，填写“Speech text”，显示原文保持不变。

点击播放后，可以手动阅读或自动推进。常用键为空格或右箭头下一句、左箭头上一句、A 自动播放、S 跳过配音、L 重播本句、H 隐藏界面、R 查看原始记录、F 全屏。浏览器尚未允许声音时，先主动点击播放。

## 八 上传背景 立绘和封面

在“素材”（Assets）中选择素材类型、填写名称并上传。背景用 background，人物立绘用 standee，PDF 封面用 cover，插图用 illustration，背景音乐用 bgm。立绘应绑定角色；建议使用透明背景图片，并注明表情和素材来源。

图片支持 PNG、JPEG、WebP、GIF，单文件上限 20 MB；音频支持 WAV、MP3、OGG、FLAC、M4A，上限 50 MB，仍受服务器整体上传限制约束。PDF 使用的单张图片还要小于或等于 10 MB。

演出选择器只列出已批准的相关素材。上传后没有出现在下拉框时，检查审批状态、类型和角色绑定。AI 生成的候选图由 KP 审核；批准与“共享给玩家”是两个独立操作。需要用于玩家公开成品的素材，必须具有合适的可见范围。

可以先建立战役视觉风格档案，并保存角色固定外观。没有图像服务时，上传素材仍可完成制作。Mock 图片是明确标记的测试图案，不是真实 AI 美术。

## 九 配置角色声音和合成配音

配音以“演出”为单位，因此只有项目或快照时，先按上一节创建演出。首次制作最好由 KP 完成角色及旁白的配置。

1. 打开“配音工作室”（Voice studio），在“新声音档案”中填写名称、选择角色和预设音色，再点击“创建声音档案”。为旁白创建一个未绑定角色的档案；这个操作仅 KP 可以完成。
2. 在试听文本框输入一小段中文，点击对应档案的 audition。确认当前是 Qwen 还是 Mock。
3. 如果有专有名词，先创建发音字典，每行写“原词=读法”，例如 `Cthulhu=克苏鲁`。创建声音档案时选择该字典。字典只影响朗读文字，不替换聊天显示原文。
4. 到“批量配音”选择演出，点击“估算”。检查需合成行数、缓存命中、字符数及是否在预算内，再点击“合成配音”。
5. 等待任务完成，回到视觉小说打开演出播放。重新播放使用已保存音频，不会再次调用 TTS。

系统按台词角色匹配声音，旁白和骰点可使用未绑定角色的旁白档案。某些句子没有配音时，先检查人物映射、声音绑定、台词是否隐藏及任务错误。

角色的稳定音色指令放在声音档案中；单句的低声、迟疑或惊讶放在演出里的 Delivery instruction。修改后重新估算并提交任务，参数相同的音频会复用缓存。“即使已配音也重新生成”会重新检查和关联音频，不保证绕过相同请求的缓存。

测试服务器的 Mock TTS 只产生测试音调，不会读出人声。使用真实 Qwen 需要管理员配置密钥、模型和区域，并由 KP 允许该战役云端处理。金额显示未知时不等于免费；应用的字符预算也不等于供应商账单。声音设计、复刻和方言取决于实际模型能力，复刻还需提交声音权利人与授权说明。

## 十 定制 PDF

先在作品库打开要导出的快照，再进入 PDF。内置模板中，classic 用于传统染色记录，dossier 用于调查档案风格，novel 用于小说式排版。

页面可以设置 A4、A5 或 B5，横向或纵向，衬线或无衬线字体，字号、行距、页边距，以及标题、副标题、页眉、页脚。可控制 OOC、时间戳、目录、页码、章节分页和骰点的显示方式。当前没有任意上传字体的界面。

封面字段填写素材 ID。素材库中 KP 可看到 ID；选择已经批准且符合快照阅读范围的图片。展开“角色颜色与场景插图”后，可以填写 JSON 映射：角色颜色以 speaker key 对应十六进制颜色，场景插图以 scene key 对应图片 ID。键来自项目中的发言者与场景列表，不是直接填写人物昵称。编辑后点击输入框外，使设置生效。

KP 可以点击“保存模板”复用配置。点击“渲染 PDF”才会生成新的排版结果；改变设置不会直接改变已生成的文件。任务完成后用“预览”检查结果，再下载真正可搜索文字的 PDF。

文档附录只收录当前权限允许的 confirmed 或 resolved 条目。KP 附录用于守秘人私有导出，玩家组附录绑定该组及其版本；玩家公开快照不能附带这些知识文档，带知识附录的 PDF 也不能发布为分享成品。玩家换组后，旧组附录的访问会失效。第一次制作公开 PDF 时保持附录未勾选最直接。

## 十一 发布和撤回

本地下载与平台发布是两个操作。需要在平台里供别人阅读时，由 KP 到“已发布”（Published）填写标题，选择染色记录、PDF 或已有视觉小说，再选择受众。

“频道玩家”要求登录并拥有频道权限；“仅 GM”只供守秘人；“持链接者”允许获得链接的人打开。“持链接者”和“频道玩家”都要求玩家公开快照。发布 PDF 时选择同一快照下已完成的 PDF；发布视觉小说时先选中对应演出。

点击“发布选定快照”后，成品固定当时的内容和资源版本。之后继续编辑不会静默更新这个成品。需要更新就制作新版本并重新发布；旧版可点击“撤回发布”。撤回会关闭平台内容和资源链接，但不能收回别人已经下载的文件。

## 十二 遇到问题时

“请先选择项目”或“请先打开快照”：回作品库，先点击项目，再点击快照的“查看”。顶部会显示当前项目和快照版本。

新聊天没出现在成品里：重新同步事件并创建新快照。仅刷新网页不会让旧快照增加内容。

PDF 一直 pending：PDF 渲染 Worker 可能没有运行，或无法连接后端。请管理员检查 Worker 和后端使用的任务令牌；这与有没有 TTS 密钥无关。

配音只发出音调：当前是 Mock 模式。更换试听文字不会把 Mock 变成真人语音。

生成或发布被拒绝：先检查云端制作开关、快照范围、素材审批和可见范围；不要通过反复更换链接尝试绕过权限。

找不到背景或立绘：检查素材类型、是否批准、人物绑定和公开范围。上传成功并不代表自动批准或共享。

界面和本指南差异很大：请核对实际运行的前端与后端提交，而不只看本地分支名。本指南对应 f0716a0；在此前的 fdee334 版本中，还没有新版剧本整理入口与 KP 置顶看板。
